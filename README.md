# ostis-example-app: график работы сотрудников ресторана

Этот проект реализует интеллектуальную систему на базе OSTIS для построения недельного графика работы персонала ресторана "Гурман". Основа README подготовлена по материалам документа `report.pdf` и сверена с текущей структурой репозитория.

## Назначение проекта

Система решает задачу составления графика смен для ресторана, который работает ежедневно в трех сменах:

- утренняя
- дневная
- ночная

Для каждой смены требуется фиксированный состав команды:

- 1 повар
- 2 официанта
- 1 уборщик
- 1 администратор

При этом учитываются ограничения предметной области:

- сотрудник может работать не более 5 смен в неделю, если в базе знаний не задан другой лимит
- доступность сотрудника зависит от типа смены
- поварам можно запретить ночные смены
- администраторам можно разрешить только дневные смены
- при недостатке персонала система фиксирует проблему укомплектования и подбирает резервных сотрудников

## Что делает агент

Ключевой агент проекта: `BuildStaffScheduleAgent`.

Он:

1. читает из sc-памяти ресторан, сотрудников, их роли, доступные типы смен и недельные лимиты
2. читает список смен и их типы
3. строит двудольный граф "сотрудники - смены"
4. расширяет граф слотами, чтобы учесть ограничение на максимальное число смен
5. решает задачу назначения через алгоритм максимального потока Dinic
6. записывает результат обратно в sc-память

Результат включает:

- назначения сотрудников на смены через `nrel_assigned_employee`
- резервных сотрудников через `nrel_reserve_employee`
- персональные недельные расписания через `nrel_employee_schedule`
- число назначенных смен через `nrel_shift_count`
- флаг полной укомплектованности через `nrel_all_shifts_staffed`
- узлы проблем укомплектования через `concept_staffing_issue`

## Формализация предметной области

В базе знаний описаны основные сущности:

- `concept_restaurant`
- `concept_employee`
- `concept_shift`
- `concept_shift_type`
- `concept_week_schedule`
- `concept_employee_slot`
- `concept_staffing_issue`

Роли сотрудников:

- `concept_cook`
- `concept_waiter`
- `concept_cleaner`
- `concept_admin`

Основные отношения:

- `nrel_has_employee` - ресторан содержит сотрудника
- `nrel_has_role` - сотруднику назначена роль
- `nrel_available_shift_type` - сотруднику разрешен тип смены
- `nrel_shift_type` - смене назначен тип
- `nrel_shift_day` - смене назначен день
- `nrel_max_shifts_per_week` - недельный лимит сотрудника
- `nrel_assigned_employee` - сотрудник назначен на смену
- `nrel_reserve_employee` - сотрудник указан как резерв
- `nrel_employee_schedule` - персональное недельное расписание
- `nrel_shift_count` - число смен сотрудника
- `nrel_all_shifts_staffed` - признак полной укомплектованности

## Структура проекта

Основные директории и файлы:

- `knowledge-base/restaurant_shift_schedule/` - предметная область графика работы ресторана
- `knowledge-base/restaurant_shift_schedule/entities/` - ресторан, сотрудники, дни, типы смен и сами смены

- `knowledge-base/restaurant_shift_schedule/concepts/relations/` - отношения предметной области

## Запуск

### Через web-интерфейс

В базе знаний определена пользовательская команда:

- `Сформировать график работы сотрудников ресторана`

После запуска системы ее можно вызвать через `sc-web`, передав ресторан в качестве аргумента. Команда связана с действием `action_build_staff_schedule`.

### Через Docker

В репозитории есть `docker-compose.yml`, который поднимает:

- `machine` на порту `8090`
- `web` на порту `8000`

Типовой запуск:

```bash
docker compose up --build
```

### Локальный запуск

В проекте предусмотрен скрипт:

```bash
./scripts/start.sh build_kb
./scripts/start.sh machine
./scripts/start.sh web
```

Сценарий предполагает, что зависимости OSTIS и артефакты сборки уже находятся в `install/` и `build/Release/`.

## Тестирование
